# Восемь предметных проверок ЛР 2

Для каждого пункта сохраните запрос, ожидаемый HTTP-статус, проверяемое поле JSON и запрос к БД, если он нужен.

1. БД доступна: GET /health/db → 200, status=ok.
2. Корректный список → 200; состав и порядок совпадают с фикстурами.
3. Фильтр без совпадений → 200, пустая коллекция.
4. Несуществующий идентификатор → 404.
5. Создание заголовка с двумя элементами → 201; в БД один заголовок и два элемента.
6. Неверное значение → 400/422 согласно контракту; в БД нет изменений.
7. Недопустимый limit либо сортировка → 400/422.
8. Ошибка второй дочерней строки → отказ; заголовок и первая строка также отсутствуют.

Для ЛР 4 дополните: свой объект, чужой объект, отсутствие токена, подмена owner_id, промежуточный отказ и два одновременных клиента. Служебный smoke.sh не заменяет эти проверки.
